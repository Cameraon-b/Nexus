## 4. Capture a matched recovery point, then restore availability

### Audit before touching writers

Backup first validates external private paths and matching Ed25519 signing/verification keys. Regular-file inputs must be canonical single-link files outside the repository/build context, with symlink components rejected and link count exactly one. This includes private configs, signing/verification/SSH keys, age identity and recipient files: an external pathname with a hard-link alias inside a build context refuses. Approved destination/temp directories are not subject to the regular-file link-count rule. The JSON backup configuration has a closed schema and six mandatory logical includes (`externalPath` and `loadBackupConfig` in `scripts/production-recovery.mjs`). Its historical `.env.example` filename does not mean it is shell or dotenv input.

Before configuration/runtime audit the producer bounded-reads and validates all six include files into one operation snapshot. It renders Compose from a private copy of those env bytes, checks the canonical password source against the rendered secret, and packages exactly the snapshotted bytes. Canonical source selection, identity/timestamps and bytes are rechecked during capture and before encryption/publication. Replacement or change refuses; failures after quiescence still restore existing-service availability. Invalid initial includes refuse without stopping writers. A crash can leave the private env snapshot in the protected stage.

The producer inspects exactly four unique full container IDs: API, frontend, PostgreSQL, and an exited/0 migration container. Image tags, immutable IDs, release labels, healthy states, and migration/API image equality must agree. It audits rendered Compose and actual runtime before capture (`backup` pre-capture audit in `scripts/production-backup.mjs`). Runtime audit checks exact networks, frontend address, commands, users/security/mount contract, and forbids extra capabilities or host namespace settings (`scripts/production-backup-audit.mjs:6-28`). This is deliberately stricter than “a container with this name exists.”

### Quiesce → capture → restart → publish

The implementation's order is the recovery invariant:

1. Measure database size **before** stopping writers.
2. Stop the exact project's frontend and API; confirm their original IDs are stopped and PostgreSQL remains healthy.
3. Capture the eleven counts, custom-format dump, and Data Protection keys. Validate the dump with `pg_restore --list`.
4. Repeat counts and key fingerprint; require equality.
5. In `finally`, start the existing API/frontend with `start --wait`, without build, pull, or recreation; re-audit original IDs/configuration/images and runtime health.
6. Only then assemble, encrypt, sign, and publish the backup.

The concrete sequence is the quiesce/capture/restart section of `backup` in `scripts/production-backup.mjs`. Keys are captured through a networkless, read-only-root helper using the immutable PostgreSQL image, UID/GID 1654, dropped capabilities, and a read-only mount of only the exact keys volume (`capture` helper inside `backup` in `scripts/production-backup.mjs`).

A restart failure refuses publication and returns `NEXUS_BACKUP_AVAILABILITY`. If private cleanup also fails, availability remains the primary error and the cleanup warning is preserved (`backup` catch/finally cleanup in `scripts/production-backup.mjs`; `scripts/production-operation-outcome.mjs:1-18`). An apparently successful archive must never mask a stopped application. Handled capture failures exercise the restart path; process death or power loss can still interrupt it and needs operator recovery.

## 5. Confidentiality and producer authenticity are different promises

### Age encryption: no plaintext archive file

The producer builds a bounded tar Buffer in memory and passes it to age on stdin with a stable recipient copy, not the mutable configured pathname. Before capture/quiescence, the canonical external single-link recipient is bounded-read (nonempty, 64 KiB inclusive maximum), its identity and exact bytes captured, SHA-256 compared to the independently approved durable `recipientFingerprint` in external backup config before any Docker call, and a 0600 copy staged in the private 0700 operation directory. Source identity and bytes are rechecked at every include-stability checkpoint and before publication; replacement/content drift refuses. Age validates recipient syntax; the repository does not impose a recipient grammar or record contents in metadata/logs. A private env snapshot is staged for consistent Compose rendering; both copies are removed before exact staged quartet inventory/publication, or with the stage on handled failure. Restrict Windows inherited ACLs separately; POSIX modes alone do not establish them. Ciphertext, checksum sidecar, authenticated plaintext metadata and detached signature complete the quartet, bounded/verified before the first publication link. There is no plaintext recovery archive on disk (`backup` in `scripts/production-backup.mjs`). The encrypted age identity stays off-host; its user-controlled passphrase is never recorded.

This is **bounded in-memory processing, not streaming**: database preflight ceiling 192 MiB, archive ceiling 512 MiB, includes 1 MiB each, key tar 16 MiB, XML key 64 KiB, and external commands normally bounded to five minutes (`scripts/production-backup.mjs:24-27`, the exported size bounds and `backup` capture section in `scripts/production-backup.mjs`; `scripts/production-key-xml.mjs:2-6`). Memory, swap, core dumps, and host storage protections still matter. Cleanup is not forensic erasure.

### Signed quartets, not merely checksums

A usable backup comprises exactly:

```text
nexus-backup-YYYYMMDDTHHMMSSZ.tar.age
nexus-backup-YYYYMMDDTHHMMSSZ.tar.age.sha256
nexus-backup-YYYYMMDDTHHMMSSZ.metadata.json
nexus-backup-YYYYMMDDTHHMMSSZ.signature.json
```

Age keeps content confidential; SHA-256 detects corruption; **Ed25519 with an independently pinned public key authenticates the producer**. The producer's PKCS#8 private key remains protected on Nora. Before Docker/quiescence, regular single-link external signing/verifier files are descriptor-read with a 64 KiB bound, identity-checked, and matched. Signing uses only those approved private bytes; all producer envelope checks use a private in-memory snapshot of those exact public bytes. Key identity and bytes are rechecked at critical points and immediately before success; identical-byte or matched-pair substitution refuses. Private signing bytes are never staged or archived (`scripts/production-key-snapshot.mjs:1-21`, `scripts/production-backup.mjs:49-68`, `scripts/production-backup.mjs:139-154`). The off-host verifier gets only its SPKI public key, authenticated independently of the backup store.

The canonical signed payload is a fixed-order UTF-8 JSON array containing domain/version, artifact name, project, creation time, ciphertext hash, **exact metadata-file byte hash**, and metadata version. Attestation schema and canonical 64-byte base64 signature are checked (`scripts/production-signing.mjs:3-27`). Metadata cannot acquire authority merely because its JSON parses. ## 12. Remaining limits and operator decisions

- A backup is confidential/authentic only while age custody, signing custody, trusted pins, verifier code, and private ACLs remain sound. Neither identity contents, passphrases, signing/SSH keys, database passwords, credentials, push tokens/URLs, nor recovered private content belongs in reports or Git.
- Aggregate equality is a strong observable check, not row-by-row equivalence or protection against an operator bypassing the lock and directly writing PostgreSQL. A structural key check/fingerprint is not an authenticated-session recovery test.
- The rehearsal did not replace production, test a real NPM configuration import, or demonstrate cookie/session/CSRF recovery over recovered HTTPS. Keep Secure cookies unchanged and review any future ephemeral TLS acceptance separately.
- Small-deployment memory limits are intentional. Larger databases need reviewed streaming tooling. Rootless Docker, clocks, disk capacity, swap/core-dump controls, host keys, and unattended scheduler behavior remain operational responsibilities.
- Handled failures attempt exact cleanup/restart; crashes can leave locks, stopped services, partial encrypted publication, or private restore material. Never steal a lock merely because it is old. Establish owner/child-process absence, recover only the exact project, and verify resource absence before deleting private material.
- Root installation is per client; no CA revocation service exists. Kuma still needs trusted TLS. HSTS excludes subdomains deliberately. Young retention history and the unauthorized missed-run enhancement remain explicit limitations, not hidden incomplete promises.
- Sprint 10 owner acceptance and local-main/Gitea publication are complete; no application upgrade is implied. Production remains on Sprint 8. GitHub synchronization remains Cameron-managed and was not performed by Hermes.
